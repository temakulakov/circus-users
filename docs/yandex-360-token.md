# Как получить токен Yandex 360

Приложению нужен один OAuth-токен Яндекс ID с правами на каталог организации. Через него
оно проверяет занятость логинов, заводит почтовые ящики, добавляет людей в рассылки и
отключает уволенных.

«Сервисные приложения» из админки Яндекс 360 для этого **не нужны**: они выдают токены
на час и предназначены для работы от имени сотрудников — Диск, Почта, Календарь. Управление
каталогом устроено иначе.

## 1. Под какой учётной записью

Токен принадлежит человеку и наследует его права в организации. Значит, входить нужно
администратором организации Яндекс 360.

Лучше завести **отдельную служебную учётную запись администратора** и выпускать токен под
ней. Токен, привязанный к личному аккаунту, умирает вместе с ним: человек уволился, сменил
пароль, включил дополнительную защиту — и приложение перестаёт заводить почту, обычно в
самый неподходящий момент.

## 2. Зарегистрировать приложение

Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) под этой учётной
записью.

1. **Название** — например, `circus-users`.
2. **Платформа** — «Веб-сервисы».
3. **Redirect URI** — нажмите ссылку **«Подставить URL для отладки»**, подставится
   `https://oauth.yandex.ru/verification_code`. Своего сайта не нужно: токен получают
   вручную, приложение его по сети не принимает.
4. **Доступ к данным** — найдите **Яндекс 360 Directory API** и отметьте права:

| Право | Зачем |
|---|---|
| `directory:read_users` | список занятых логинов и псевдонимов — проверка занятости при вводе ФИО |
| `directory:write_users` | создание ящика с паролем, отключение сотрудника при увольнении |
| `directory:read_groups` | список рассылок в шаблонах подразделений |
| `directory:write_groups` | добавление нового сотрудника в рассылки |

Больше ничего не отмечайте. Права на Диск, Почту и Календарь приложению не нужны, а токен
с ними — лишний риск.

`directory:read_departments` можно добавить, если позже понадобится выбирать подразделение
Яндекса из списка, а не задавать числом. Сейчас приложение этот метод не вызывает.

5. Создайте приложение и скопируйте **ClientID** с его страницы.

**Client secret не нужен.** Мы используем неявный поток, секрет в нём не участвует, и в коде
приложения его нет.

## 3. Получить токен

Откройте в браузере, где вы вошли администратором:

```
https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID
```

Яндекс покажет экран подтверждения со списком запрошенных прав — сверьте, что там ровно то,
что вы отмечали. После «Разрешить» откроется страница с токеном; он же виден в адресной
строке после `#access_token=`.

**Скопируйте токен сразу.** Повторно его нигде не посмотреть. Потеряли — пройдите по той же
ссылке ещё раз и получите новый, старый при этом продолжит работать.

Рядом с токеном страница показывает `expires_in` — срок жизни в секундах. Запишите дату
окончания в напоминания: когда токен истечёт, приложение начнёт отвечать «токен
недействителен или истёк».

Выданные токены видны на [oauth.yandex.ru/client](https://oauth.yandex.ru/client). Там же
приложение удаляется целиком, что мгновенно гасит все его токены.

## 4. Ввести в приложение

Настройки → **Корпоративная почта** (раздел виден только администратору) → вставьте токен →
**Сохранить** → **Проверить**.

Токен ложится в диспетчер учётных данных Windows под ключом `circus-users:yandex360`,
зашифрованный на вашу учётную запись Windows. В файлах приложения и в репозитории его нет,
с другой машины не прочитать. Читается он на каждом запросе, поэтому замена действует
сразу, без перезапуска.

## 5. Проверить идентификатор организации

`Mail:OrgId` в `appsettings.Local.json` — **числовой** идентификатор из админки
[admin.yandex.ru](https://admin.yandex.ru); он виден в адресной строке и в профиле
организации. Не путайте с идентификатором организации Yandex Cloud вида `b1g3ar…` — формат
совсем другой.

Кнопка «Проверить» делает один безобидный запрос на чтение и сразу показывает, принят ли
токен и найдена ли организация.

## Если что-то не так

| Что показывает приложение | Что это значит |
|---|---|
| токен недействителен или истёк | Срок вышел или приложение удалили на oauth.yandex.ru — выпустите новый |
| у токена нет прав на управление сотрудниками | При регистрации не отметили нужное право; поправьте права приложения и получите токен заново |
| организация не найдена — проверьте orgId | В `Mail:OrgId` не тот идентификатор: нужен числовой из админки |
| такой логин уже занят | Ящик с таким адресом есть; смените логин вручную на форме создания |
| превышен лимит запросов | Слишком частые обращения, повторите через минуту |

Ошибка вида «Ошибка проверки поля … Это поле является обязательным» при заведении ящика
означает не отсутствие поля, а то, что API не прочитал тело запроса. Такое уже случалось:
шлюз Яндекса не принимает тело, отправленное порциями, без `Content-Length`. Приложение
отправляет его одним блоком, и на это есть тесты; если ошибка появится снова, смотрите
`Yandex360MailService.JsonBody`.

## Порядок первого запуска

1. Ввести токен, нажать «Проверить» — это только чтение, ничего не создаёт.
2. Завести одного заведомо ненужного сотрудника и убедиться, что ящик появился.
3. Только потом заводить настоящих людей.

Отказ почты не отменяет уже созданную учётную запись в домене: человек остаётся, а в
диалоге появляется предупреждение с причиной. Такие случаи пишутся в `audit.log` строкой
«Ящик не создан» вместе с телом запроса без пароля — по ней видно, кому ящик нужно завести
руками.
