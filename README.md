# circus-users

Настольное приложение для управления учётными записями сотрудников: заводит человека
одновременно в Active Directory и в корпоративной почте Yandex 360, показывает адресную
книгу и хранит шаблоны подразделений.

WinUI 3 (Windows App SDK), .NET 8, MVVM. Вход только доменный — форм логина нет,
набор доступных страниц зависит от членства в группе администраторов.

> **Настройки своей организации сюда не кладут.** `appsettings.json` в репозитории содержит
> только значения по умолчанию с пустыми полями. Реальные — корневой DN каталога, имя группы
> администраторов, идентификатор организации в Yandex 360 — кладутся в `appsettings.Local.json`
> рядом с ним: этот файл перекрывает основной и не отслеживается git. Секретов нет ни там,
> ни там: токен почты лежит в диспетчере учётных данных Windows, пароли не сохраняются нигде.

## Что умеет

**Добавить пользователя** (только администратор). По полю ФИО в порядке «Фамилия Имя
Отчество» пересчитываются имя, фамилия, логин и почта: транслитерация по фиксированной
таблице, логин вида `i.ivanov`. Если логин занят, префикс имени наращивается — `iv.ivanov`,
`iva.ivanov`, — и под полем видно, что именно занято. Занятость проверяется сразу в трёх
местах: учётная запись в каталоге, почтовый адрес в каталоге и логин в почтовой организации.
Учётная запись создаётся в AD, затем вторым шагом заводится почтовый ящик; сбой почты не
отменяет уже созданного человека, а возвращается предупреждением с возможностью повторить
только почтовую часть. Пароли — разные для домена и почты — показываются один раз.

**Адресная книга** (всем). Таблица с поиском и группировкой по подразделению. Подразделение
определяется по OU, в котором лежит учётная запись: атрибут `department` в каталоге заполнен
далеко не у всех. Колонки настраиваются под себя, у администратора есть правка по карандашу,
действия «заблокировать» и «уволить» и кнопка «применить вид для всех» — она не затирает
персональные настройки тех, кто их менял.

**Настройка подразделений** (только администратор). Дерево OU и шаблон нового сотрудника:
организация, городской телефон, город, адрес, кабинет, руководитель (поиск по справочнику),
группы Active Directory и группы рассылки Yandex — оба списка с поиском и галочками.
Шаблон хранится в служебном contact-объекте внутри самого OU; контакт создаётся при первом
сохранении. Переключатель «Это подразделение» помечает служебные каталоги: в них нельзя
завести сотрудника, они исчезают из выбора при создании и не получают служебный контакт.
Отметка действует только на сам каталог — вложенные её не наследуют.

**Настройки.** Тема, прозрачность (Mica, Mica Alt, акрил, выключено, синхронно с системой),
акцентный цвет с готовой палитрой и своими пресетами, расположение навигации, звуки
интерфейса, токен почты и переключатель тестового режима.

## Где что лежит

| Данные | Место | Почему |
|---|---|---|
| Токен Yandex 360 | Диспетчер учётных данных Windows | Шифруется под учётной записью, с другой машины не читается |
| Шаблон подразделения | Атрибут `info` контакта внутри OU | Едет вместе с каталогом, права на него — обычные права на объект |
| Реестр подразделений | `departments.json` на общей шаре | Каталог, помеченный «не отдел», не должен получать объектов, поэтому отметке внутри него не место |
| Общий вид книги | JSON на общей шаре | Один вид на всех, задаёт администратор |
| Личные настройки | `LocalState` приложения | У каждого свои |
| Журнал операций | `audit.log` на общей шаре | Записи всех администраторов вместе |

Пароли не пишутся ни в журнал, ни в логи, ни на диск.

## Структура

```
Circus.Users.Core/        Логика, не зависящая от интерфейса
  Abstractions/           Интерфейсы: каталог, почта, шаблоны, реестр, секреты
  ActiveDirectory/        Чтение, запись, кэш, шаблоны подразделений
  Yandex/                 Yandex 360 Directory API
  Naming/                 Транслитерация, генерация логина и пароля
  Fakes/                  Тестовый режим: те же интерфейсы, ничего не меняют
circus-users/             Приложение WinUI 3
Circus.Users.Core.Tests/  xUnit
```

Тестовый и боевой режимы переключаются на лету: запись идёт через прокси, который выбирает
реализацию на каждый вызов, поэтому перезапуск не нужен. В любом диалоге, который что-то
меняет, видно, куда именно уйдут изменения.

## Сборка

```bash
dotnet build circus-users.sln -c Debug -p:Platform=x64
dotnet test Circus.Users.Core.Tests/Circus.Users.Core.Tests.csproj
```

Приложение упаковано как MSIX; из Visual Studio запускается по F5. Сборку, которую можно
просто скопировать и запустить без установки, даёт публикация без пакета:

```bash
dotnet publish circus-users/circus-users.csproj -c Release -p:Platform=x64 -r win-x64 --self-contained true -p:WindowsPackageType=None -p:WindowsAppSDKSelfContained=true
```

## Настройка

Скопируйте `circus-users/appsettings.json` в `circus-users/appsettings.Local.json` и заполните
значениями своей организации — достаточно тех ключей, которые отличаются. Второй файл
перекрывает первый и в репозиторий не попадает.

| Ключ | Смысл |
|---|---|
| `ActiveDirectory:DomainFqdn` | Пусто — домен берётся с компьютера |
| `ActiveDirectory:UsersBaseDn` | Корень поиска сотрудников |
| `ActiveDirectory:AdminGroup` | Группа, дающая права администратора приложения |
| `ActiveDirectory:CacheRefreshMinutes` | Как часто перечитывается справочник |
| `Mail:OrgId` | Числовой идентификатор организации Yandex 360 |
| `Mail:DefaultDepartmentId` | Подразделение для новых ящиков; `1` — корневое |
| `Storage:SharedSettingsPath` | Папка общих настроек и журнала |

Токен почты вводится в настройках приложения администратором, в конфиге его нет.
Права токена: `directory:read_users`, `directory:write_users`, `directory:read_groups`,
`directory:write_groups`.
